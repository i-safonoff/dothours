# Как вести разработку

[🇬🇧 English](CONTRIBUTING.md) · 🇷🇺 **Русский**

## Настройка

```bash
make install
cp .env.example .env
poetry run pre-commit install
docker compose up -d db redis   # если не хотите поднимать весь стек
make migrate
```

## Рабочий цикл

1. Ветка от `main`: `feat/…`, `fix/…`, `docs/…`, `chore/…`.
2. Перед пушем: `make lint` и `make test`.
3. PR по шаблону — что, зачем и как проверить.

## Договорённости по коду

**Роут владеет транзакцией, сервис — нет.** Сервисы делают `flush()`, но не
`commit()`. Благодаря этому одну и ту же логику вызывают и HTTP-ручка, и
Celery-задача, и тест.

**Кэш обновляется в момент события, а не на чтении.** `CityBuilding`,
`DailyProgress`, счётчики лайков — материализованное состояние. Если хочется
посчитать агрегат на лету, сначала прикиньте, как это выглядит на пользователе
с годом истории.

**Продуктовый конфиг — в коде, а не в таблице.** Уровни зданий и районы города
— настройка продукта, не пользовательские данные.

**Комментарий объясняет «почему», а не «что».** Код и так говорит, что он
делает; ценно то, почему выбран именно этот вариант и что было отвергнуто.

**Осознанное упрощение проговаривается.** Если что-то сделано «пока просто» —
скажите в комментарии, при каком условии это придётся переделать.

## Модели и миграции

Поменяли модель — сделайте миграцию:

```bash
make migration m="add something"
make migrate
poetry run alembic check    # должно быть «No new upgrade operations detected»
```

Две вещи, на которых легко обжечься:

- **Переиспользование существующего enum-типа.** Если тип уже создан прошлой
  ревизией, колонку нужно объявлять как
  `postgresql.ENUM(..., name="...", create_type=False)`. Иначе ревизия пройдёт
  на чистой базе и упадёт на любой существующей.
- **Несколько голов.** Ветвление даёт `alembic heads` с двумя записями. Чините
  до мержа: перецепите `down_revision` или сделайте `alembic merge`.

CI проверяет и то, и другое: накатывает миграции по одной ревизии за раз на
настоящем PostgreSQL и прогоняет полный цикл downgrade/upgrade.

## Тесты

Тесты работают на SQLite в памяти — внешние сервисы не нужны, весь прогон
занимает секунды.

- Фоновые задачи тестируются вызовом функций из `app/worker/jobs.py` напрямую,
  с подставленным «сейчас». Ни брокера, ни eager-режима Celery.
- Реалтайм тестируется на внутрипроцессной шине (`WS_BACKEND=memory`).
- Метрики глобальны на процесс, поэтому проверяйте прирост, а не абсолютное
  значение.

Тест должен падать по делу: описывайте поведение, а не реализацию. Название —
предложение о том, что гарантируется (`test_owner_cannot_leave_before_handover`).
